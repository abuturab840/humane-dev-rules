Before every release

Release checklist

24 checks to run before you ship. Copy them into your release notes.

Go through this list before every release (rule 48Rule 48. Always. The person doing the release goes through the release checklist and saves the result with the release. For big launches, a second person checks it too. Working alone? Check it again the next day with fresh eyes. in the rules).

  1. Copy the list into your release notes, pull request or a note you keep with the release.
  2. Tick each item that's done.
  3. Write "n/a" next to anything that doesn't apply to your project, for example the AI items on a site with no AI.
  4. If an item applies and isn't done, fix it before you ship. If you really can't, write down why and the date you'll fix it by (rule 35Rule 35. Always. Never ship with a known critical or high security problem. If you really must make an exception, write down why and the date it runs out.).

Working alone? Run it again the next day with fresh eyes before a big launch.
